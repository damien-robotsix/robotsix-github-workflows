# robotsix-github-workflows doc memory

## Repo layout & doc conventions
- Tier: workflow-library (reusable `workflow_call` YAML only; no runtime code/package/image).
- `README.md` holds a table of reusable workflows; each `X` row links to `docs/workflow-reference.md#X-yml` (strip dots: `baseline-check.yml` → `baseline-checkyml`, `modules-drift.yml` → `modules-driftyml`).
- `docs/workflow-reference.md` has one `## \`X.yml\`` section per workflow: | Input | Type | Default | Description | table, optional | Secret | table, `### Caller template` YAML snippet, and a `**Consumer prerequisites:**` list. New workflows MUST be added here.
- `CHANGELOG.md` is historical (release-please generated) — never rewrite past entries.

## Authoring rules triggered by doc-convention checks
- **Pinning**: every `uses:` is a 40-char SHA + trailing `# vX.Y.Z` comment. Caller templates use the `<sha-of-vX.Y.Z> # vX.Y.Z` placeholder. Local `./` refs are exempt; own-repo composite-action refs SHA-pin with no comment.
- **No inline `${{ }}` in `run:`** — pass via `env:`.
- **`persist-credentials: false`** on every `actions/checkout`.
- **Job-level `if:` guards** over workflow-level conditions (Rule 4).
- **Static `workflow_call` defaults** (Rule 5); dynamic defaults via `default: ""` + runtime fallback.
- **`timeout-minutes: 15`** fleet default on every job (docker-release `publish` is 20).
- Wrapper workflows: consumers trigger on `push` branches main + `pull_request` which call the reusable.

## Workflow layout observed
- `baseline-check.yml`: `has-docker` input, single `baseline` job (AGENT.md, README, LICENSE MIT, dependabot ecosystems, release-please-config, .secrets-patterns-excluded).
- `modules-drift.yml`: standalone `workflow_call` with `python-version` (3.14) + `uv-version` (0.12.5) inputs; job runs `uv sync --frozen` then `uv run --frozen robotsix-modules validate|check-registration|validate-paths docs/modules.yaml --root .`. No baseline scaffolding.
- Other workflows: python-ci, python-security, python-docs, release-please, docker-release, docker-pr-scan, scan-container, codeql, scorecard, dependency-review, config-ownership-check, lint-workflows, lint-dockerfile, mutation-test, deps-bump, bump, pin-bump, pin-bump-sweep, dependabot-auto-merge.
